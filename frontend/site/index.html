How to use LogSentinel

  1. Add logs. On Analyze logs, paste HDFS log lines or choose a log file (up to 5 MB / 50,000 lines). Not sure what to try? Click Load example logs.
  2. Click Analyze. LogSentinel groups the lines by HDFS block (one block = one “session”) and checks each block's story.
  3. Read the summary. It shows how many lines were read, how many sessions were found and how many look like problems.
  4. Look at the sessions. Red rows (Problem) are likely problems; orange rows (Borderline) are just below the problem threshold and worth a look. The Risk bar shows how confident the model is.
  5. Click a session to see why: the log events that pushed it towards “problem”, in plain words.

What do the words mean?

Block / session
HDFS stores files in pieces called blocks. All log lines about one block form its “session”.
Problem (anomaly)
A block whose events look unlike healthy blocks — for example a failed write, a timeout or an unexpected deletion.
Risk
How strongly the model believes the block has a problem (0–100%).
Unseen events
Log messages the model has never seen before. Many of them can mean the system changed and the model may need retraining.

Something went wrong?

  • “None of the lines look like HDFS log lines” – check that each line starts with date, time, process id, level and component, like the example.
  • “The anomaly model is not available” – the model service is starting or stopped. Wait a minute and try again, or ask the administrator.
  • “Too many lines” / “File too large” – split the file into smaller parts.
